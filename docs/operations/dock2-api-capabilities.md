# Dock 2 司空公有云 V2 能力核对

核对日期：2026-09-28。官方 [API 目录](https://s.apifox.cn/4de4a239-c2cc-4572-9b65-90738289f37a/llms.txt) 的 89 个接口 ID 与本仓库 endpoints.tsv 相同。范围限定为中国大陆公有云；接口目录存在、代码已接入、当前账号允许、设备现场成功是四个不同状态。

## 设备分类

| 分类 | 型号 | 目标与能力 |
|---|---|---|
| 机场本体 | DJI Dock 2 | 目录、物模型、HMS、机场相机、直播、RTK、航线任务；通用飞行控制以机场 SN 为目标 |
| 配套飞行器 | Matrice 3D / 3TD | 飞行器状态、相机目录、负载控制权、镜头切换；通用飞行指令通过机场执行 |
| 相机负载 | Dock 2 Camera、3D / 3TD Camera、Vision Assist | 只使用上游发现的相机索引、视频频道和镜头类型；不能凭型号补出不存在的频道 |
| 环境传感器 | Dock 2 Environment Sensor | 通过物模型读取实际返回的环境数据，没有独立执行飞行的控制能力 |
| 其他型号 | Dock 3、Matrice 4 系列、中继等 | 当前新增分类目录不声明为已验证支持 |

3D 不提供红外相机；3TD 的实际红外频道仍需以上游目录为准。

## 不能从现有公开目录推出的能力

公有云 V2 目录与实时控制枚举没有舱盖开关、飞行器上下电、充电、调试模式、声光报警、机场重启的接口。此前按钮来自 DJI Cloud API 的设备型号能力目录；这不证明司空 OpenAPI 提供同样指令。不得把 cover_open 等 Cloud API MQTT 方法塞入仅允许四种枚举的 HTTP device_command。

中继对频虽然有官方接口，但不是 Dock 2 常规能力；官方配对结果查询说明仅适用于私有云与中继场景。本次不纳入 Dock 2 操作列表。

## 本地真实情况

2026-09-28 本地项目 1 认领 Dock 2 与 Matrice 3TD，各一台，状态在线。能力证据包含目录/组织查询成功，状态查询有成功与未验证记录；HMS/TCA 有空结果。设备控制、相机/镜头、RTK、飞行任务写入没有 field-write 现场证据。

本次只核对官方文档、代码和已有只读证据，没有发送任何设备写指令。接口接入与验证情况记录在本文档中，设备与实时作业页面只展示可用操作和必要提示；HTTP API 与 worker 都拒绝以飞行器型号作为机场通用指令目标。

## 实时作业入口复核（补齐前）

2026-09-28 再次在线读取官方目录：89 个接口 ID 与仓库契约完全一致。浏览器和本地设备树 API 显示的情况如下，不能将适配层已实现理解为用户已经能在页面执行：

| 操作 | 当前缺口 |
|---|---|
| 机场相机、飞行器镜头切换 | 前端 TypeScript 目录有定义，服务端实际使用的 capability_actions.json 没有这两项，投影出的 actions 为空 |
| 取消返航、暂停、恢复 | HTTP/worker 有策略和适配，实际菜单没有对应定义 |
| 返航 | M3TD 声明了能力但不是接口的机场目标；本地 Dock 2 没有 flight.return_home 能力记录，无法通过当前能力菜单发起 |
| 设备控制授权 | DeviceActionPanel 未提交 approvalRequestId 和 safetyPolicyVersionId，不能满足现有 API 的精确设备审批与安全策略校验 |
| 控制可用性 | 设备树检查相机前置条件，实时 snapshot 没有执行相同检查，二者的可用性提示可能不一致 |
| 负载控制权、画质、RTK、项目绑定维护 | 存在独立适配，但实时作业没有完整交互入口 |

本地相机与镜头切换功能开关为 true，对应 field-write 验证记录为 false；本次读取 M3TD 状态超过控制要求的 30 秒，机场状态当时仍新鲜。现场验证、状态新鲜度、审批以及安全策略仍由服务端执行检查。本次没有修改开关、伪造验证记录或下发物理控制指令。

## 实时作业入口补齐

实时页按设备型号分组展示操作：Dock 2 提供返航、取消返航、暂停与恢复任务、机场相机切换、画质、网络 RTK 标定与项目绑定；Matrice 3D/3TD 提供负载控制权、镜头切换与画质。机场相机索引从已发现的视频频道选择，镜头参数使用上游真实 lens_type。

手动操作流程为填写参数后直接执行，按当前用户 RBAC 鉴权，不需要另一个成员审批。后端记录操作者、设备、参数摘要和执行回执；敏感参数加密保存，页面隐藏 RTK 密码。现有任务账本的授权外键复用为明确标记 authorizationMode=rbac 的直接操作授权记录，不创建待审批申请，也不插入人工审批票。执行仍检查权限、开关、现场证据与设备状态；飞行控制保留安全策略校验，相机和镜头切换不要求飞行安全策略。幂等键绑定操作者与精确参数。页面展示操作记录及控制权续期/释放入口。智能体写工具仍要求用户手动授权。

Dock 2 的返航能力已补入型号和已绑定设备，飞行任务暂停/恢复可在存在活动任务时通过安全检查。实时 snapshot 与设备树现在使用相同相机前置条件。

本地已通过直接 RBAC 执行、参数不可替换、重复执行、密码隐藏、跨项目隔离和快照集成测试，以及前端类型检查。浏览器验证了分组按钮与机场相机参数弹窗。集成测试仅向隔离数据库写入任务账本，没有发送真实设备控制；真实飞行和现场写操作仍待验收。

## 统一型号、能力与操作映射

实时操作目录不再维护一份设备型号名单；操作声明所需的设备能力及表单、功能分组。服务端从 device_types.capability_profile_json 与驱动能力声明查询型号能力，以 device_capabilities 的观测状态判断当前可用性。实例旧记录不能补回型号已取消的能力。GET 展示和 POST 执行使用相同解析函数，缺失能力时既不显示按钮，也不能通过手写请求执行。

负载控制权使用独立 camera.payload.control 能力，画质使用 stream.video.quality；类型目录和驱动声明已同步。司空命令目标限制由现有执行策略提供，避免把飞行器返航能力错误映射成机场 HTTP 指令。RBAC、开关和现场验证仍独立决定操作是否可执行。

已验证：移除型号相机能力后，残留实例相机记录不会继续显示按钮，POST 也拒绝该操作；缺失能力不产生操作，具备能力的新型号无需新增页面型号判断。

## 飞行器与机场直播

飞行器视频频道从当前设备 camera_list 或物模型中实际报告的相机索引对象映射，不再只生成机场视频频道；没有相机索引时不按型号猜测。读取发现的相机目录进入托管设备状态轮询，相机去重并保留独立设备作用域。直播观看对机场与飞行器采用同一权限/功能开关检查，不要求负载写操作现场验证；飞行控制与镜头切换的验证条件仍保留。

实时作业展示项目内已开启的多路直播，每一路使用所属设备与频道；切换作业设备不会把另一设备的直播面板筛掉。2026-09-28 经用户授权实测：机场频道 165-0-7 已在本地浏览器播放真实视频，并停止观看，随后确认远端 inactive。飞行器目录报告 offline、camera_list=null，启动返回 213003（no streaming gateway found）；缓存 OSD 相机索引不能证明当前可直播，现降为 degraded 并禁用启动。业务错误先于成功 data 校验，213003 明确记为失败；未取得播放授权的停止会话终止本地等待，并保留远端状态未确认的原因。离线设备的缓存 OSD 不再产生在线心跳。未验证两路同时播放。

实时作业的飞行控制按机场关联飞行器的最新模式与同一连接器任务状态筛选：正常可返航的飞行状态显示返航，返航中显示取消返航；航线执行中显示暂停，暂停后显示恢复。待机、未连接、降落及状态过期时隐藏不适用指令。GET 与 POST 共用状态判断，提交时状态变化返回 409；活动航线任务使用在线轮询间隔更新状态。已通过状态组合与本机 PG 集成测试，浏览器确认当前未连接飞行器不再显示四个飞行控制按钮。
