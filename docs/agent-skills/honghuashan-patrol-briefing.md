# 红花山巡检准备

## 适用请求
“今天怎么巡红花山”“检查园区巡检准备情况”“给监控室做巡检安排”。将业务目标转为当前项目可执行的检查建议。

## 输入与范围
确认公园/园区、关注区域、时间窗、无人机与固定摄像头来源。用户未说明时先按当前项目只读检查，不假设项目就是红花山，也不杜撰区域坐标。红花山为可选演示案例，其他园区复用流程。

## 工作步骤
1. 调用 query_devices、query_tasks、query_assets、query_map_context 获取真实设备状态、已有任务、资产和区域；按需 query_tracks。设备在线不等于可飞，不等于存在实时视频。
2. 如用户需要执行条件检查，调用 query_inspection 的 readiness；先使用工具 schema，不臆造必填字段。区分设备新鲜度、可用影像、任务准备与飞行授权。
3. 围绕游客通道、环境设施、烟火夜间线索提出优先级，必要时通过 list_skills / load_skill 加载对应专项 Skill，避免把所有流程同时塞入上下文。
4. 输出“已有资源、关注区域、建议任务、证据缺口、下一步”五项。每个已有事实附真实来源链接或平台引用；建议与事实分开。

## 输出与约束
用简短监控室值班简报。没有实时来源时明确“基于现有资产”，不要称实时巡查完成。只提供计划建议，不创建或执行飞行。任何写操作继续遵循平台真实工具与用户确认流程；Skill 不授予权限。多路并行检测及 DGX 本地推理属于部署能力，未验证前不得宣称已运行或给出性能数字。
