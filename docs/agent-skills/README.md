# 红花山公园巡检演示 Skills

资料核对日期：2026-10-10。场景由用户确认：团队实际在深圳光明红花山公园开展无人机巡查。下列五项为现有平台能力上的任务流程配置；平台级启用，实际检索仍限当前会话项目，不把其他项目自动视为红花山。

## 业务依据

- [深圳光明：红花山公园](https://www.szgm.gov.cn/zjgm/lsgm_118488/cygm_118492/jqjd/content/post_8760551.html)：公明街道城市公园，包含儿童活动、草坪、园路及服务设施。公开介绍不能用于推断实时客流、开放时间或精确围栏。
- [公司：红花山无人机驾驶培训](https://www.xieyingtech.cn/archives/1741681325274)：2024 年公司在红花山开展安保人员培训，覆盖飞行理论、操控和巡逻应用，是实际业务结合点。
- [公司：游客救助案例](https://www.xieyingtech.cn/archives/1741681834033)：红花山巡逻发现游客异常，经监控室与值班负责人协调地面救助，支撑证据交接与人工处置流程。
- [公司：护林清理垃圾活动](https://www.xieyingtech.cn/archives/1741681750387)：活动地点为凤凰径五段，作为环境巡查工作参考，不能写成红花山已发生事件。
- [深圳官方：低空经济赋能公园](https://www.sz.gov.cn/szzt2010/szcycx/cxdt/content/post_11908290.html)：其他深圳公园已探索无人机巡查园容、设施、游客安全与护林防火；行业实践不等于本平台已实现全部能力。

## 现场叙事与实际边界

路演建议顺序：自然语言请求 → 按需加载 Skill → 查询多源证据 → 地图/片段回放 → 监控室交接。录屏优先演示游客通道与证据交接，长版再加入环境或烟火复核。

可直接使用的演示提问：

1. “加载红花山巡检准备，先检查当前项目可用设备和地图区域，列出数据缺口。只读检查。”
2. “加载红花山游客与通道复核，从已有成功检测结果找人车线索，查看真实画面，返回可回放片段；位置不明就说明。”
3. “加载红花山事件证据交接，把刚才真实检索到的线索整理成监控室简报，区分事实和待核查项，不发送通知。”

现有素材是否为红花山、是否有绝对时间及定位，要在录屏前核实。不能为了地理展示将别处素材移到红花山，也不能把普通人车检测演示包装成烟火、垃圾专项模型已上线。

DGX 目标部署：监控室就地部署，批量处理多路无人机与固定摄像头数据，检测、视觉复核和索引构建共享任务队列。用实际测试的并发路数、分辨率、抽帧率、完成延迟、内存峰值与模型常驻情况证明价值。现有线上配置使用何种云模型/CPU 必须如实说明；这些 Skills 本身不会把推理变为本地，也不会产生尚未接入的实时数据。真实航拍若缺采集时间或定位，只能展示片段相对时间和位置缺口。
