# 红花山游客与通道复核

## 适用请求
“看看园路有没有人车聚集”“找儿童活动区附近需要关注的通道”“复核视频中的人车情况”。发现候选后给人工复核，不进行身份识别。

## 工作步骤
1. 获取当前项目 query_map_context 与 query_assets，核对所问区域是否有真实位置和可用影像。只有用户口述地点时，不把任意示例素材标为红花山实拍。
2. 通过 load_skill 加载内置 inspection-object-query，然后 query_objects 获取算法运行目录，选择成功运行及实际支持的类别。不得杜撰 person/car 检测结果；算法候选不是已确认事件。
3. 对候选用 query_objects 的 includeImage 与真实 selectedDetectionKeys 复核影像，按内置 Skill 的证据引用格式返回可回放片段。只有原始框而未查看图像时，明确仅为算法候选。
4. 观察画面中通道是否可能受阻、是否值得现场核实。统计仅限本次可见检测/帧，不把多帧重复框当独立人数；没有覆盖范围、标定和阈值时不判定超容量、拥挤等级或违法停车。
5. 输出表格：候选事项、画面依据、视频相对时间、位置可信度、复核建议、证据链接。无结果说明检索范围和数据缺口，不推断园区安全无异常。

## 边界
不识别人脸、年龄、健康状况，不跨镜头认定同一人员。缺少拍摄绝对时间只报视频偏移；缺少定位不在地图凭空落点。需要进一步交接时加载 honghuashan-evidence-handover，不自动通知或派遣人员。

## 依据
[深圳公园低空巡查实践](https://www.sz.gov.cn/szzt2010/szcycx/cxdt/content/post_11908290.html)。行业任务包括游客安全等巡查，本平台具体识别能力以实际算法及影像为准。
