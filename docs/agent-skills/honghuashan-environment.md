# 红花山环境与设施巡查

## 适用请求
“找园区垃圾和道路障碍”“整理需要检查的设施”“公园环境巡查简报”。以已有资产形成可核查清单。

## 工作步骤
1. query_assets 与 query_map_context 核对素材、区域和设施记录，先区分真实红花山资料与其他演示素材。
2. search_media 分项检索“散落垃圾”“道路障碍”“倒伏枝条”“设施损坏”等用户关注内容。模型描述只用于召回，不能直接写成现场事实。
3. 根据实际支持的影像工具核对候选证据；需要算法对象时先加载 inspection-object-query，查询成功运行及支持类别。没有垃圾/损坏检测模型，不能声称已有自动识别结果。
4. 对可見片段说明观察依据、视频偏移、位置是否可信、遮挡和覆盖限制。画面无法判定的设施内部故障、树木病害或结构安全交由现场人员检查。
5. 输出“待复核事项、证据片段、建议检查位置、建议处理工种、缺口”。只有确有证据时描述疑似问题；没有结果则给针对性补拍/人工检查建议。

## 边界
不虚构坐标、缺陷数量或清理完成状态。不自动创建案件或派工；用户要求执行时仅使用平台实际存在并获授权的动作。证据交接可加载 honghuashan-evidence-handover。

## 依据
[公司护林清洁活动](https://www.xieyingtech.cn/archives/1741681750387)、[深圳公园低空实践](https://www.sz.gov.cn/szzt2010/szcycx/cxdt/content/post_11908290.html)。清洁活动发生于凤凰径五段，仅用于任务流程参考，不描述为红花山事件。
