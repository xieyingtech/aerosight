# 红花山事件证据交接

## 适用请求
“把巡查线索整理给监控室”“生成事件复核简报”“汇总需要地面人员确认的情况”。将检索结果转成可回放、可追溯的人工交接材料。

## 工作步骤
1. 以当前会话实际工具结果或用户提供的证据标识为输入。需要补查时 query_issues、query_tasks、query_assets，或 query_inspection 获取确切 observation/evidence_set/report；使用真实 schema，不猜记录 ID。
2. 建立证据清单：来源设备/资产、观察事项、绝对采集时间或视频偏移、位置与可信度、真实平台引用。资产上传时间不等于事件发生时间。
3. 分开“已核实事实、算法/语义候选、人工待核查、建议行动”。没有实际影像复核或坐标时明确缺口，引用不能证明的内容不得补写。
4. 形成值班简报：情况、证据、需要谁核查、建议下一步、回执要点。园区负责人/地面队伍只是建议角色，不捏造人员姓名、电话、到场时间或处理结果。
5. 用户要求更新现有案件时，先读当前版本，再使用平台支持的实际操作与确认流程。只读演示停在简报；不调用不存在的建案工具，不直接发消息，不启动无人机。

## 输出
一段简报加证据表。链接应能回到当前项目对应片段/记录。没有线索也可生成“数据缺口与补采建议”，不得制造事件来凑演示。无授权不得跨项目取证；不认定跨镜头同一人员，不输出无关身份信息。

## 依据
[公司红花山游客救助案例](https://www.xieyingtech.cn/archives/1741681834033)：参考巡逻人员发现情况、监控室协调、地面队伍协作的交接链路，不能把历史案例当当前平台报警。
