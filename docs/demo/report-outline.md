# AeroSight 项目报告大纲

定位：完整的时空智能巡检平台框架，以一条真实业务闭环展示模块协同。
建议标题：AeroSight：面向无人机巡检的时空数据与智能体协同平台。
篇幅暂按 10–12 页设计；比赛要求确定后调整。本文为写作/配图大纲，不是最终效果报告。

## 统一叙述口径

开篇摘要：AeroSight 面向无人机巡检中设备、影像、算法与业务处置相互割裂的问题，构建统一的时空智能巡检平台。平台组织设备连接、数据资产、空间展示、算法服务、智能体、任务编排、工单和报告等模块，通过统一的项目范围、版本与运行记录建立协作关系。本文以历史航拍人车巡查为实例，展示从数据输入、视觉检测、智能研判到人工复核、工单和报告的完整业务流程，并明确记录实际验证范围。

平台能力按三类标注：已有实现、已完成实测、规划/待验证。只有通过真实验收的案例才能写“已打通”。YOLO 为复用模型；StepFun TTS 用于视频制作，不作为平台内置业务模块。

## 架构图绘制说明

- 左侧输入：司空/其他连接器、历史文件导入。实线表示本案例已验证的输入，虚线表示待接通路径。
- 中间底座：项目、设备、数据资产、时空信息；算法中心和智能体中心并列。
- 上层编排：Task（YAML/参数表单）→ trigger → Run → step，连接 observe/detect/assess/issue/report。
- 右侧业务：复核、Issue、处置反馈、报告与证据回溯。
- 不画成“一个 YOLO 服务加一个聊天窗口”；突出已有模块的资源与执行关系。

## 写作禁区与替代表达

- 不写“全自动完成无人机起飞至处置”，写“本案例验证历史素材分析与业务处置闭环；飞行接入单列”。
- 不写“自主研发 YOLO 识别算法”，写“通过算法 Provider 接入本地视觉模型”。
- 不写“人车检测等于违规检测”，写“提供目标证据与待核查线索”。
- 不写“完整框架即全部功能成熟”，用实现/实测/规划标识分别说明。
- 不把截图展示当性能或识别效果证明；效果数据独立测量。
