## 补录 A：技能加载与类别查询

建议素材：同一张具有清晰人车目标的实际可用影像，识别成功的 YOLO Run。可先使用 DGX 演示项目中的公开 bus 样图（非实飞照片）；用于行业演示时换成授权航拍照片并重新识别。

提示词：

> 查询当前项目已完成识别的影像，帮我找出人和车辆，返回目标框与筛选依据。

镜头：输入自然语言 → load_skill → query_objects → 展开工具摘要 → 打开“查看目标框与筛选结果”。

验收：类别标签与真实结果一致；使用真实运行 ID；框的位置、数量和结果表一致。没有匹配时只说“本次检测候选中未找到”。

旁白：

> 我们把巡检人员核对范围、检查证据、复核结果的经验封装成 Skill。智能体先加载专业流程，再调用真实检测结果，给出可以回查的目标框。

## 补录 B：追问筛选与交付

同一会话追问：

> 查询同一运行中的人：只保留站在画面中间、穿黑色外套的人。请查看整图和对应裁剪，按实际目标 ID 筛选，返回目标框链接和依据。

镜头：保持原运行 → query_objects 的实际目标 ID 选择 → 新结果链接 → 只叠加选中框 → “导出待核查清单”。

已实测正例：本机项目1，bus.jpg，运行 `02de111b-08e5-4143-b4b2-8de209b529f5`，4个人中保留目标 ID `0`，结果页显示1框，导出1条待核查记录。此人黑色外套内搭红色衣服，旁白使用“黑色外套”，避免说“纯黑上衣”。公开样图不是无人机实拍。截图见 object-query-positive.png。

可选零匹配追问：

> 只保留车辆，其他目标去掉，给我筛选后的目标框和待核查清单。

本次样图虽然能看到公交车，但已有检测运行只记录4个人。实测返回0个车辆候选；不能将“候选中未找到”说成“图中没有车辆”。此镜头用于展示证据边界，不建议作为主功能正例。

可选车辆属性复核（需换用确有车辆候选的成功运行后实测）：

> 只保留画面中红色的车辆，说明每个保留目标的依据；看不清的列为待复核。

模型会按需收到经版本校验的整图与最多8个目标裁剪，选择时只能引用真实候选 ID。颜色和场景判断属于模型辅助，不能用类别标签冒充已看图。

## 补录 C：行业规则而非“检测即违规”

> 这些目标能直接认定为违规吗？还缺哪些核查依据？

预期：引用 Skill 的实际边界，区分检测事实与业务结论；缺区域管理规则、时间和历史资料时明确需要核查。只有单期图像不能认定“新增”或“长期停放”。不为了演示伪造工单或违规结论。

## 分工与介绍口径

- DGX Spark：已验证部署的 YOLO GPU 图像检测；耗时使用当前真实 Run/服务记录。
- StepFun：配置的 step-5-preview 理解需求、调用工具、组织结果；请求图像复核时图像会发送至当前 AI Provider，不能说全程离线或影像永不出本地。
- Skills：业务流程、证据规则、异常处理与交付要求；本轮新增 inspection-object-query v1.0.0。
- AeroSight／设备平台：设备/航线/素材查询，执行授权，状态反馈，结果与证据保存。
- 本轮实现为“已有检测候选＋自然语言筛选＋按需视觉复核”。Grounding DINO、OWLv2 开放词汇检测是扩展方案，尚未部署，不能说现在支持任意物体定位。
- 现有录像证明已展示的飞行操作；影像分析使用历史图像时标明来源，不宣称已实现本次飞行实时视频连续识别或自动飞行到报告的全部闭环。
