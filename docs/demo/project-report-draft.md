# AeroSight 低空巡检感知与决策协同平台

参赛队伍：一只汤圆叮

所属学校：大连理工大学

## 让低空感知连接业务决策

低空巡检带来丰富的图像与空间信息。业务真正需要的，是从这些数据中找到值得关注的线索，理解线索的含义，并组织后续处理。AeroSight 围绕这一需求，将时空数据、算法服务、智能体、任务编排与工单协作组织在统一平台中。

平台以项目作为业务容器，以 Task 作为流程载体，以证据关联作为模块之间的纽带。用户既能管理数据与智能能力，也能把它们组合成可重复执行的巡检流程。产品价值体现在三个方面：让能力可以组合，让判断有依据，让结果能够进入业务协作。

本文以园区航拍巡检为例，介绍平台如何将影像依次转化为检测证据、研判建议、工单与报告。这个案例体现的是完整框架中的一条应用路径；统一的组织方式也为不同巡检场景提供了扩展基础。

## 平台架构与模块协同

AeroSight 的架构围绕数据、能力、流程和业务四个层次展开。接入层连接外部平台与文件素材，数据层通过项目组织设备和资产，能力层管理算法与智能体，流程层使用任务编排它们，业务层承接复核、工单与报告。

数据资产为每个分析任务提供明确输入；算法服务将图像转化为结构化证据；智能体结合上下文形成处理建议；Task 定义步骤顺序与依赖；工单和报告让结果进入协作。这些模块拥有各自清晰的职责，又通过输入输出关系保持关联。

平台采用组合式设计。司空等外部平台承担专业飞行与媒体基础能力，AeroSight 聚焦上层业务流程和决策协作。算法通过服务接口接入，业务流程通过任务定义组织，使外部能力能够进入统一工作流。

这种分工有利于按场景选择工具：同一个业务框架可以连接不同的算法服务，同一种智能能力也可以被多个任务复用。

## 时空数据：为分析建立上下文

在巡检业务中，图片的价值来自它与时间、来源、项目和观察范围之间的关系。平台将素材作为数据资产管理，并保留版本和来源信息，使每次分析拥有确定的输入。

观察范围描述本次任务分析的对象与时段。它将一个宽泛的巡检目标收敛为明确的数据集合，使后续检测与研判围绕共同上下文展开。时间与空间属性帮助组织业务语义，版本与来源关系帮助追溯处理过程。

在园区案例中，用户选取航拍影像作为任务输入。系统建立观察范围，再将同一份素材交给视觉算法。后续打开检测、研判或工单时，均能沿关联关系回到原始图像。

这种组织方式让素材从静态文件成为流程中的共享依据，减少跨模块重复整理信息的工作。

## 视觉感知：将影像转化为证据

算法中心把视觉模型封装为可调用的服务能力。任务提交图像与参数，服务返回目标类别、位置和置信度，平台将结果与原始素材关联展示。

园区案例采用 YOLO 识别道路中的车辆。目标框使用户能够直观定位模型关注的区域，类别与置信度提供进一步核对的线索。图像、检测结果与算法版本共同构成后续研判可引用的证据。

视觉能力与业务任务通过接口解耦。任务关注调用哪种能力、使用哪些输入、如何处理输出；模型服务关注如何完成识别。面向不同业务场景，可以选择相应算法，而不必重新设计整条业务流程。

算法中心的价值因此不仅在于运行一个模型，也在于让视觉感知成为平台中可组合、可追踪的基础能力。

## 智能体研判与人机协同

视觉检测回答图像中有哪些目标，业务研判进一步组织哪些线索需要关注、依据是什么以及下一步如何处理。AeroSight 将观察范围、检测证据和任务要求交给智能体，形成面向业务的结构化建议。

建议保留理由与证据引用，使使用者能够从结论返回依据。这样的输出便于连接后续流程，也便于人员理解和审查。智能体在这里承担从感知结果到业务语义的转换角色。

复核界面将原始建议、证据入口与处理选项集中呈现。人员可以确认线索、调整建议或排除目标，并记录理由。修订记录保留判断演变过程，使协作经验和具体决策建立关联。

人机协同贯穿流程：算法发现目标，智能体组织建议，人员作出关键判断。平台以统一的证据关联将三种角色连接起来，让专业经验自然进入自动化流程。

## Task 编排：把能力组织成流程

Task 是平台的流程单元。用户通过 YAML 描述触发器、步骤、能力名称与参数，并通过参数表单调整配置。语法沿用开发者熟悉的工作流编辑习惯，使流程既便于原始编辑，也便于在界面中理解。

触发器回答何时开始执行，步骤描述具体执行内容，依赖关系描述输出如何传递。手动和定时是同一流程的不同启动方式。用户可以先组织业务步骤，再根据场景配置触发方式。

园区巡检流程由观察、检测、研判、工单与报告组成。观察步骤确定输入范围，检测步骤形成证据，研判步骤输出建议，工单承接确认后的线索，报告汇总任务结果。步骤之间通过输出引用建立联系。

发布版本与运行记录分别承载流程定义和执行过程。任务因此能够从一次操作沉淀为可重复使用的业务方法，运行工作台则帮助使用者理解每次执行的状态与产物。

## 工单与报告：让结果进入业务协作

经过确认的线索进入工单，成为持续跟踪的业务对象。工单汇聚描述、状态与证据入口，为沟通和后续处理建立共同上下文。

从工单可以回到研判建议，继续查看检测证据与原始图像。这种关联把发现问题、理解问题和处理问题连接起来，让不同角色围绕同一份依据开展工作。

报告汇总任务观察范围、识别结果、研判内容和关联工单，提供整体视图。运行工作台记录各步骤的输入、输出与状态，为理解流程提供另一条入口。

工单关注具体线索的持续协作，报告关注一次任务的结果表达，运行记录关注过程。三者共同让巡检成果从分散信息沉淀为可查询的业务记录。

## 创新设计与应用价值

第一，以证据关联贯穿感知与决策。素材、检测、研判、修订和工单之间保留来源关系，使业务结果具有可解释的上下文，也让跨角色沟通围绕共同依据展开。

第二，以任务编排连接独立能力。算法与智能体通过服务化接口进入任务，触发器和步骤将它们组合成业务流程。能力可以替换和复用，流程可以根据场景调整。

第三，将人机协作纳入自动化流程。人工判断通过明确的复核环节进入任务，建议与修订相互关联，使人员经验成为流程的组成部分。

第四，采用开放的平台分工。AeroSight 复用专业平台与模型能力，聚焦业务组织、决策协作和成果沉淀。项目、资产、能力和流程由此形成统一框架，为园区、设施与城市巡检等场景提供共同的产品基础。

平台的核心主张是：以任务连接能力，以证据连接决策，让每一次巡检产生持续价值。

## 典型流程与产品体验

使用者首先在项目中组织数据与所需能力，再配置巡检任务。任务启动后，观察范围明确输入，视觉服务生成识别证据，智能体组织业务建议，人员在需要时进行复核，结果进入工单并汇总成报告。

产品体验围绕这条业务路径展开。数据页面回答分析什么，检测页面回答发现什么，研判与复核页面回答如何理解，工单页面回答如何协作，报告与运行页面回答整体结果和过程。

各页面通过证据与任务关系连接，帮助用户在概览和细节之间切换。AeroSight 由此将底层感知能力与上层业务行动组织在同一个工作环境中。
