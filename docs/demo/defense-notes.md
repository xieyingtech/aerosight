# 高校组路演与答辩要点

路演 5 分钟，答辩 2 分钟；每个回答控制在 20–30 秒，先回答核心问题，再给一条证据。以下为当前状态的答题口径，真实验收后可更新。

## 1. 这和直接在司空里看照片有什么不同？

我们复用司空的设备和飞行能力，重点是把数据、可替换算法、智能体和工单组织成统一流程。案例展示的价值是同一次任务从输入到报告都能关联证据，识别结果能够进入复核与处置。不能笼统声称司空没有类似能力，我们提供的是跨能力、跨流程的组织方式。

## 2. 大模型具体做了什么，而不只是生成文字？

模型消费结构化检测证据与巡查上下文，输出可校验的业务建议和引用；结果决定后续进入工单还是人工复核。模型与提示版本保留，业务写入由正式流程执行。实际模型协议已测试，最终路演必须补上真实检测证据到决定的运行记录。

## 3. 为什么符合“时空智能”？

输入来自低空航拍，分析保留采集时间、位置来源和任务关系，决策能回溯到具体观察。当前不把地图展示等同于空间推理，也不宣称照片坐标就是目标坐标。区域关系、多期对比与飞行决策仍需进一步验证，当前验证重点是感知证据到业务决策的协同。

## 4. 是全自动飞行吗？

本次案例使用历史航拍素材，重点验证分析和业务处置闭环。新飞行的自动调度与回传单列接入和现场验收。定时分析与真实飞行是两种不同能力，材料中明确区分。

## 5. 用现成 YOLO，创新在哪里？

YOLO 是复用的基础能力，创新主张在平台协作机制：算法产生证据、智能体研判、任务编排执行、人工复核和工单承接，并通过来源与版本回溯。我们不把现成模型作为自研成果，也需要用真实闭环证明这些机制的实际价值。

## 6. 模型误判怎么办？

检测和业务结论分开：车辆存在不等于违规。缺少上下文时进入复核，保留模型原始输出和人工决定。效果评测记录误报和漏报；失败不能冒充零检测，有限图片范围不能推导整个区域无异常。

## 7. 完成度如何？

平台已有资源、算法、智能体、Task、工单和报告等模块及软件测试。真实文本模型调用已验证，本地 YOLO 和真实全链仍在联调。最终答辩以证据登记表为准，已通过的部分才改为完成；不要背诵过时状态。

## 8. 如何落地和扩展？

先服务园区和巡检团队，以项目部署、流程配置和算法集成为落地方式，再接入更多设备与业务模型。目前商业模式是待验证假设，没有把未发生的客户收入或效率提升写入成果。

## 路演人员提示

开头先展示平台版图，主体讲一个案例，结束回到框架复用。演示视频配音不替代现场成员表达；官网要求每项目 1 名成员路演，是否可全程播放配音视频须另核对现场安排。准备可手动讲解的版本，以及真实完成 Run 的备用回放。
