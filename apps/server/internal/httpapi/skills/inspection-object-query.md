# 巡检目标查询与复核

## 何时使用

用户要求找人、车辆或其他检测目标，按颜色、位置、上下文筛选，或追问“只保留这些目标”。

## 专业流程

1. 明确用户要查哪次运行或哪张影像。调用 query_objects（不填 algorithmRunId）读取运行目录，不能凭空编造 ID；如无可用识别，查询 query_inspection.algorithms 和 query_assets，再通过 run_algorithm 请求用户点击授权识别，不自动启动飞行。
2. 对选定成功运行调用 query_objects。labels 使用实际模型标签（如 person、car、truck、bus），车辆通常包含多个类别。未知类别不得说已全面检索。minConfidence 默认 0，不要悄悄提高阈值以排除低置信度目标。
3. 类别、置信度由工具确定性筛选。includeImage=true 会将经 checksum/版本核验的整图和最多 8 张候选裁剪发送给当前 AI Provider；检测可能在 DGX 本地，图像复核不是完全本地。先看 visualStatus、previewedDetectionKeys 和未覆盖数量，图像不可用或未看过的候选不得判断颜色、衣着、占道等属性。
4. 仅从实际候选中选择 detectionKey。颜色、场景关系使用整图与对应裁剪综合判断；bbox 是原图像素坐标，不能当作经纬度。需要区域筛选时使用用户明确的图像区域，不捏造地理边界。
5. 用同一 algorithmRunId 再调用 query_objects，selectedDetectionKeys 填实际保留 ID，selectionReason 填简短理由。空数组表示本次零匹配，不能省略或替换成所有目标。只基于真实候选，不生成新框。
6. 交付匹配数量、选择理由、筛选结果链接、未覆盖/待复核项；使用 Markdown 可点击链接 `[查看目标框与筛选结果](工具返回的href)`，不要把链接包在代码块或反引号中。没有匹配只能说“在本次检测候选中未找到”，不能说整片区域绝对没有目标。
7. 追问时保持原运行不变，重新读取候选与图像，保留此前筛选条件并明确修改；不能把 detectionKey 在不同运行间混用。

## 行业判断边界

- 检测到人车是感知事实；是否违规依赖实际管理规则、区域用途、时间和人工核查。
- 单期图像不认定“新增”“长期停放”；缺历史数据或规则时说明缺口。
- 模糊、小目标、遮挡返回需要复核或补拍建议；预测置信度不是违规概率。
- 清单为待核查候选，创建或修改案件仍走既有用户点击授权。

## 验收

同一运行先查“人和车辆”，再追问“只保留车辆”，结果链接打开后只出现验证过的框；零匹配保留空清单。所有结论能回链到运行、素材版本和目标 ID。
