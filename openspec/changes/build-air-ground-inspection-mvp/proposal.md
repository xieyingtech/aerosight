## Why

AeroSight 当前已经具备项目、设备、任务、资产、案件和智能体会话的管理骨架，但尚不能通过统一任务编排控制真实无人机执行巡检、查看直播、调用外部算法并把满足条件的结果转成可协作案件。首期需要先把“任务触发—设备采集—算法处理—条件判断—案件协作—时空智能体辅助”做成可运行闭环，同时以统一设备 Adapter、Pose 和 Track 契约为后续 ROS 机器人、固定摄像头及空地协同保留扩展点。

## What Changes

- 建立项目级设备连接与数字孪生能力；首期实现 simulator 与 DJI Adapter，统一接收无人机状态、遥测、能力、心跳和命令确认，定义但不交付 ROS 2、MQTT、MAVLink、RTSP/GB28181 的生产 Adapter。
- 建立统一的时空观测模型，保存采集时间、接收时间、坐标系、位姿、精度、来源和置信度，并支持按项目、时间和空间范围检索及回放。
- 建立直播会话、采集资产、缩略图和证据链管理，使图片、视频片段和其他成果可关联到设备、任务运行、目标和案件。
- 将现有 Tasks 与任务运行扩展为平台唯一的声明式编排层，支持手动、定时、API/Webhook 和 Copilot 委派触发，使用版本化模板、类型化输入、顺序步骤、步骤输出引用和条件表达式编排设备能力、数据采集、算法调用、案件创建、Copilot 分析与报告生成。
- 建立可配置的算法服务统一框架，管理员可按 `type`、`baseUrl`、凭据、模型/进程和输入输出映射接入 HTTP JSON、Open Inference Protocol/KServe V2、OGC API Processes 或 AI SDK 算法服务。
- 首期交付疑似违建识别任务模板：巡检媒体作为步骤输出传入算法服务，标准化结果经确定性条件判断后创建或更新可回溯原始媒体与模型版本的案件；平台不直接给出法律意义上的违建结论。
- 将进入项目后的默认页面升级为“时空总览”：地图统一展示无人机、未来 ROS 机器人和其他移动设备的当前位置与运行轨迹，底部时间线同步展示设备 Pose/Track、任务、直播/媒体、检测和案件，并支持实时与历史回放。
- 建立项目级业务导航，包含总览、实时作业、任务、设备、连接器、案件、算法服务、智能体、数据资产和设置。
- 使用 AI SDK 建立受控 Copilot：智能体页提供项目级对话；案件允许评论、提及 `@copilot` 或把负责人指派给 Copilot。每次 Copilot 调用都由用户显式发起或写入已发布任务模板，并在执行时重新校验用户、团队、项目和细粒度权限；模型不得绕过任务预检、审批或命令账本控制设备。
- 在平台管理后台统一配置 AI Provider、基础地址、默认模型和 API Key，Agent Provider Registry 从数据库读取当前启用配置，不再通过环境变量配置 AI。设备连接器、算法 Provider 和 AI Provider 的凭据统一使用由现有 `AUTH_SECRET` 派生密钥的 AES-256-GCM 加密后存入数据库；读取时不返回凭据，编辑表单的敏感输入始终为空，留空保持原值，填写才覆盖。
- 删除项目级自动 AI 开关和 Automation Policy 模式。需要自动调用 AI 时，在 Tasks 中配置 Copilot 步骤；需要临时协助时，在案件中提及或指派 Copilot。首期所有高风险处置仍要求人工确认与既有安全流程。
- 建立覆盖租户隔离、项目权限、命令审计、数据保留和合规字段的治理能力。
- 采用向后兼容迁移；现有项目、设备、任务、资产、问题和智能体数据继续有效，不删除或重新解释已有记录。
- 非目标：首期不实现真实 ROS 机器人控制、空地目标融合、自动机器人派遣、城市级无人机交通管理、UOM 生产对接、雷达/5G-A 通感融合、全自主无人机集群、模型训练平台、通用三维重建或无人工复核的高风险处置。

用户将能够进入项目后在时空总览查看无人机与移动设备轨迹，通过 Tasks 配置和运行“巡检—采集—算法—条件—案件”流程，在案件中像协作 Issue 一样评论、指派人员或 `@copilot`，并沿时间线回放完整过程。

## Capabilities

### New Capabilities

- `device-connectivity`: 统一设备 Adapter、连接状态、能力声明、遥测、Pose、命令确认和数字孪生行为；首期生产接入聚焦 DJI。
- `spatiotemporal-observation`: 统一时空观测、位姿、坐标参考、质量元数据、空间查询和回放行为。
- `media-evidence`: 直播会话、媒体资产摄取、派生物、证据关联、访问控制和保留行为。
- `inspection-mission`: 通用 Tasks 模板、触发器、类型化输入、顺序/条件步骤、设备与算法能力调用、运行状态机、命令确认和人工安全闸门。
- `perception-event`: 外部算法服务配置与运行、疑似违建标准结果、任务条件消费、案件创建/更新、评论和证据可追溯行为。
- `operations-console`: 项目侧边栏、时空总览、实时地图、多类移动设备轨迹、直播、案件工作台、统一时间线和历史回放行为。
- `spatiotemporal-agent`: 基于 AI SDK 的项目聊天、案件 `@copilot`/指派、通过 Tasks 调度授权能力和逐工具 scope 鉴权行为。
- `safety-audit-governance`: 项目授权、命令审计、幂等控制、数据保留、合规元数据和紧急停止行为。

### Modified Capabilities

当前 `openspec/specs/` 下没有已归档能力规格，本变更不修改既有能力规格。

## Impact

- 数据库：扩展 `devices`、`tasks`、`task_runs`、`task_steps`、`assets`、`issues` 和 `issue_events`，并新增连接、遥测、位姿、观测、直播、算法 Provider/Definition/Run、检测、目标、轨迹、命令、审批和审计相关表；既有 `event_rules`、`perception_events` 与 Automation Policy 结构仅为历史兼容保留且不再承担主动编排；所有项目资源必须携带并校验 `project_id`。
- Web：重构项目布局和侧边栏，新增时空总览、实时作业、Tasks、设备、连接器、案件、算法服务、智能体、数据资产与设置页面；总览使用地图和时间线统一呈现时空数据，设置页不提供自动 AI 配置。
- Worker：Go worker 负责异步摄取、Task 条件评估、媒体派生、任务调度、报告生成和重试，不把长耗时处理放入 Next.js 请求链路。
- 外部接口：定义版本化设备适配器协议和算法服务协议；首个生产设备适配器支持 DJI Cloud API，开发和自动化测试使用 simulator；算法 Adapter 首期支持通用 HTTP JSON，并为 KServe V2、OGC API Processes 和 AI SDK 提供标准类型。
- 基础设施：PostgreSQL 启用 PostGIS；媒体和大型成果存入 S3 兼容对象存储；实时消息使用可持久化消息总线，直播媒体不经过数据库。
- AI：Web 引入 AI SDK 及数据库驱动的 Provider Registry；AI Provider 由平台管理员在管理后台配置且不读取 AI 环境变量。AI API Key 与其他外部服务凭据一样加密存库，且不通过读取 API、日志、审计摘要或智能体上下文暴露；聊天、案件委派和任务 Copilot 步骤均绑定服务端创建的用户/项目 scope，不存在绕过 Tasks 的第二套自动化引擎。
- 权限与租户：延续 User → Team membership → Project 的边界；成员可查看和处置被授权项目，只有 owner/admin 或具备项目操作权限的成员可配置适配器、改变安全策略或批准受保护命令。
- 兼容性：通过增量迁移和可空外键保持现有数据与页面可用；新实时能力在缺少外部基础设施时以明确的 unavailable/degraded 状态降级。
