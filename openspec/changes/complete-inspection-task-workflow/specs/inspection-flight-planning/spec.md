## Purpose

将航线规划与飞行执行交给已接入的司空平台，规范 AeroSight 对预设航线、已完成飞行和新派发架次的引用及状态，确保复用外部能力时仍能确定观察范围和业务运行归属。

## ADDED Requirements

### Requirement: 复用外部航线与既有飞行

系统 SHALL 支持选择项目授权的司空预设航线或既有飞行；区域覆盖和巡逻航线在司空编辑，本次不要求本地生成航线。新飞行冻结可比较的航线身份/版本并在执行前校验。

#### Scenario: 选择区域航线

- **GIVEN** 用户已在司空创建区域航线
- **WHEN** 在 AeroSight 模板选择并发布
- **THEN** 保存航线引用和可比较版本，显示来源，选择预览不触发飞行

#### Scenario: 航线失效

- **GIVEN** 航线被改动、删除、不可验证版本或不属当前项目
- **WHEN** 准备执行
- **THEN** 阻止下发并要求重新选择或确认发布，不默默使用新航线

### Requirement: 动作授权及飞行状态

系统 SHALL 复用现有司空动作入口、预检和授权机制提交一次 immediate 飞行并保存远端身份。ACK、飞行终态和媒体就绪必须区分；业务取消不得显示为飞机已经停止。

#### Scenario: 预检后提交

- **GIVEN** 能力可用、授权有效且预检允许
- **WHEN** 飞行步骤执行并收到 ACK
- **THEN** 显示已提交及远端 UUID，继续等待飞行与媒体，不提前完成观察

#### Scenario: 预检阻塞或取消

- **GIVEN** 预检有阻断错误、设备冲突或远端仍在飞行
- **WHEN** 提交或取消业务 Run
- **THEN** 有阻断时不下发；取消后明确远端可能仍在飞行，提供司空/已验收控制入口

### Requirement: 远端归属和完整性

系统 SHALL 通过项目、连接器及 flight UUID 关联业务步骤，保留投影身份；成功飞行与可靠媒体对账均满足才标架次完整。计数缺失、截断或缺图必须暴露。

#### Scenario: 完整回传

- **GIVEN** 成功架次的预期/上传计数口径可靠且全部选定媒体可读
- **WHEN** 完成文件对账
- **THEN** 观察清单封闭并进入检测，重复媒体不新增条目

#### Scenario: 回传不完整

- **GIVEN** 媒体未上传齐、计数不可核实或列表触及截断上限
- **WHEN** 到达等待截止
- **THEN** 不得标全架次完整；暂停/失败，或由用户明确确认有限范围并标 partial 后继续
