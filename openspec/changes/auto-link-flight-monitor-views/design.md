## Context

relatedLiveDevices 已能解析服务端拓扑，但当前工作台没有使用它。projectMonitorViews 仅纳入 addedViews 与活动会话，autoStart 又仅匹配初始设备 ID，因此机场飞行不会带起机载画面。

## Goals / Non-Goals

Goals：通过真实设备关系形成飞行器、机场、地图三个视角，支持延迟上线并维持用户布局。
Non-Goals：不修改飞行下发和安全校验，不新增数据表、厂商接口或权限，不以重新起飞作为软件测试。

## Decisions

1. 新增纯函数从 relatedLiveDevices 中筛选明确关联的 dock/aircraft，复用 defaultVideoChannel；只有选中设备属于该组合时才自动补齐，普通设备保持原行为。每次快照派生频道，离线阶段仍保留已声明频道，后续主相机出现时更新。
2. 工作台将派生频道与手动视角合并，自动直播意图仍锚定起飞设备的关联组合，避免手动切换任意设备导致自动启动其他设备。实际请求仍由 LiveDeviceWindow 执行并受能力与频道可用性约束。
3. 组合使用独立布局存储键，默认顺序 aircraft、dock、map，旧通用布局不覆盖新默认。用户重排后存储完整顺序；设备新上线但尚未手动重排时自动调整优先级。不按每轮快照重置组件 key，避免中断图传。
4. 沿用现有五分钟自动连接窗口、单频道启动去重与错误提示。权限、项目隔离和状态真实性继续以服务器为准。
5. 线上读取发现 identity_json.parentExternalId 正确，但 deviceRelations 为空。现有同步仅在 automatic 导入策略下写入关联，review 导入的历史设备没有补齐。同步改为对已 managed 的双方在同项目、团队、连接器范围内幂等补齐 contains，包含游标重放；不自动认领新设备，不使用位置推断关系，不执行数据库迁移。补齐依据同时校验当前已保存的父标识，避免重放旧批次覆盖新关联。

## Risks / Trade-offs

- 飞行器频道可能较晚出现：持续派生组合，在频道到达后创建播放器。
- 多台飞机关联同一机场：全部限定当前项目真实拓扑，顺序确定；不猜测活跃飞机，也不触发飞行控制。
- 双图传增加带宽：只为关联的默认相机启动，不默认启动辅助和红外等额外频道。

## Verification

纯函数测试覆盖关系过滤、离线到在线、主相机优先及布局重排。浏览器通过受控快照和拦截直播写请求验证三视角与启动次数，不使用真实飞行验证代码。线上只验证页面布局及已有会话。
