## Context

现有个人中心和项目设置均为静态客户端页面，数据由同源 Go API 提供。项目写操作使用 sqlc 和 AuditedWrite，账号由数据库持久会话管理。

## Goals / Non-Goals

目标：提供三个设置表单、明确反馈及名称刷新，保留团队管理授权与 CSRF 保护。非目标：账号登录标识变更、忘记密码、代改密码及外部服务接入。

## Decisions

- 页面默认只展示摘要和编辑按钮，显示名称、项目名称和密码均使用既有 Dialog 弹窗；提供取消/提交及 Enter 提示，提交期间禁止关闭，关闭后清理输入与错误。个人中心直接使用当前会话资料，去除重复账号及团队表格，也不再请求团队列表。

- 新增 PATCH /api/profile、POST /api/auth/password、PATCH /api/projects/:id；严格拒绝未知字段，不接受客户端用户 ID。名称按 Unicode 字符数验证。
- users 新增 credential_version 默认零；登录保存版本，requireUser 与实时会话复查读取版本。缺失版本按零处理。相比删除全部 sessions 或解析持久会话二进制，版本机制能隔离用户且防止并发请求复活旧会话。
- 密码先验证现有 bcrypt，再生成新 hash，通过旧 hash 和凭据版本条件更新，避免并发改密覆盖。账号写入记录不含密码的审计；项目写入沿用授权行锁。
- 改密成功后当前客户端返回登录页；其他旧会话下一次请求失效。UI 提示这一行为。
- 显示名称保存成功后以 API 返回的用户更新会话 provider；项目名称保存成功后广播项目更新事件，侧栏项目列表重新获取服务端数据。

## Risks / Trade-offs

- bcrypt 仅接受最多 72 字节，客户端和服务端均需按字节上限拒绝而非截断；历史短密码可作为原密码验证。
- 新迁移随正常发布执行，不连接生产试验。单调递增版本要求服务端和迁移一起发布。
- 后台领域权限不改变；所有实时入口共享版本复查，避免密码变更后持续访问。
