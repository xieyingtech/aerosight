## Purpose

提供可发现、可验证的账号和项目基础设置，让用户自行更正显示名称和更换密码，让团队管理者维护项目名称，并在保存失败、权限不足和输入无效时保持原数据完整。

## ADDED Requirements

### Requirement: 编辑个人显示名称

系统 SHALL 在个人中心提供由“修改显示名称”按钮打开的弹窗，通过 PATCH /api/profile 修改当前登录用户自身名称，去除首尾空白后允许 1–100 个 Unicode 字符；邮箱、手机号、角色和所属团队不因改名变化。个人中心 MUST 仅展示当前账号的一份资料，不显示账号或团队表格，不默认显示编辑输入框。

#### Scenario: 保存显示名称
- **GIVEN** 用户已登录并打开个人中心
- **WHEN** 输入合法显示名称并提交
- **THEN** 保存后资料及当前侧栏显示新名称，刷新仍保留该名称，并提示成功

#### Scenario: 拒绝非法输入
- **GIVEN** 用户已登录
- **WHEN** 提交空白、超长名称或额外用户 ID/角色字段
- **THEN** 返回 400 且不改变任何账号资料；界面显示完整中文错误提示

### Requirement: 自助修改密码

系统 SHALL 在个人中心提供“修改密码”按钮，在弹窗中输入原密码、新密码、确认密码，通过 POST /api/auth/password 修改当前用户密码；新密码至少 8 个字符且最多 72 字节，不允许与原密码相同，确认不一致不能提交。弹窗 MUST 支持取消，关闭后清空密码与错误；提交期间禁止关闭和重复提交。写请求 MUST 受 CSRF 和来源验证保护，密码不得回显到响应或日志。

#### Scenario: 打开与取消密码弹窗
- **GIVEN** 用户打开个人中心且没有编辑操作
- **WHEN** 点击修改密码，填写输入后取消并重新打开
- **THEN** 输入框仅出现在弹窗内；重新打开时密码和错误均为空，取消不改变密码

#### Scenario: 成功修改密码
- **GIVEN** 用户原密码正确且新密码符合要求
- **WHEN** 提交密码修改
- **THEN** 保存兼容 bcrypt 的新密码，提示成功并返回登录页；旧密码不能登录，新密码可以登录

#### Scenario: 原密码或新密码无效
- **GIVEN** 用户已登录
- **WHEN** 提交错误原密码、过短或超出字节上限的新密码
- **THEN** 拒绝修改并给出中文错误；原密码与会话仍有效

### Requirement: 授权修改项目名称

系统 SHALL 在项目设置展示名称摘要及“修改项目名称”按钮，在弹窗中通过 PATCH /api/projects/:id 修改去除首尾空白后为 1–100 个 Unicode 字符的名称。仅当前团队 owner/admin 可写入，并在同一事务重新核验成员角色及记录审计。

#### Scenario: 管理者改名
- **GIVEN** 用户是项目所属团队 owner 或 admin
- **WHEN** 保存合法项目名称
- **THEN** 项目名称和更新时间被保存，侧栏、项目列表与详情使用新名称，项目 ID、团队、权限和资源不变

#### Scenario: 越权或无效请求
- **GIVEN** 用户是普通成员、外部团队成员或提交非法名称
- **WHEN** 请求项目改名
- **THEN** 返回授权或输入错误且名称不变；平台 admin 身份和显式项目权限不能绕过团队角色限制
