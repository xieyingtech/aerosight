## Context

当前项目总览和实时作业都复用了完整的 `SituationExplorer`，导致两个页面职责近似；设备命令和直播启动又主要位于设备树中的 `DeviceActionPanel`。用户启动直播后缺少原地播放器、频道切换和清晰的设备上下文，地图上无坐标的设备也难以进入操作流程。

底层已经具备统一设备、DeviceType、Driver、能力授权、命令账本、直播会话和签名播放地址等基础设施。本次变更应重组 Web 端交互和查询投影，不新增 DJI 专属页面，也不改变 Worker 调用 DJI MQTT 与 MediaMTX 的链路。

## Goals / Non-Goals

**Goals:**

- 将项目总览收敛为只读摘要和地图。
- 将实时作业建设为单设备上下文工作台，统一承载控制、遥测、直播和诊断。
- 让操作集合由驱动能力、设备状态和服务端授权共同决定。
- 支持项目级活跃直播发现、设备视频频道启动、原地播放和频道切换。
- 让地图、搜索选择器、操作面板和播放器共享同一个可链接选择状态。
- 保留现有 RBAC、安全联锁、命令审计、直播状态机和播放鉴权。

**Non-Goals:**

- 不增加新的 DJI 飞行动作或机场动作。
- 不修改 Device、DeviceType、Driver 的领域关系或数据库结构。
- 不创建独立直播页面。
- 不重做任务规划、航线编辑或算法服务配置。
- 不让浏览器直接访问 DJI 厂商 API、MQTT Broker 或未签名媒体地址。

## Decisions

### 1. 拆分页面组件，不给 `SituationExplorer` 增加更多模式分支

项目总览使用轻量的 `OverviewMap`，只负责摘要、地图渲染和进入实时作业的入口。实时作业使用新的 `RealtimeOperationsWorkbench`，内部组合设备选择器、地图、设备面板、能力操作区、实时数据区和直播区。可复用的地图图层、设备卡片和格式化逻辑继续抽成共享组件。

没有选择给 `SituationExplorer` 增加 `mode="overview|realtime"`。该方式短期改动较少，但会继续让权限、数据订阅和交互分支纠缠，且容易让总览重新获得控制能力。

### 2. 以 URL 和客户端工作台状态共同保存单设备上下文

实时作业使用 `deviceId` 和可选 `streamId` 查询参数作为可分享入口。工作台校验服务端快照后建立本地选择状态；地图点击、搜索选择和直播切换更新同一状态并以 replace 方式同步 URL，避免每次切换污染浏览器历史。

当直播切换到另一台设备时，`deviceId` 随之更新。当设备无坐标时，地图保留当前项目视野并展示“暂无位置”，其他操作不受影响。非法、跨项目或未授权参数统一回退到未选择状态。

### 3. 服务端输出安全的有效能力与授权动作投影

项目态势快照为每台可见设备补充前端工作台所需的安全字段：设备类型/驱动显示信息、有效能力、授权动作及其可用状态和原因、视频频道摘要。能力到动作的映射复用设备树已有的服务端派生逻辑，避免两个页面各自解释能力。

投影不得包含驱动密钥、厂商凭据或内部连接配置。前端只渲染服务端投影并通过统一设备命令/直播接口执行，后端仍进行最终鉴权和联锁校验。

没有选择让前端从 `type` 或 DJI 型号推断按钮，因为这会造成策略漂移，且无法安全表达 RBAC 和动态互锁结果。

### 4. 活跃直播是项目级切换器，播放器仍受单设备上下文约束

实时作业直播区分为项目级 `ActiveStreamSwitcher` 和当前会话播放器。切换会话时同时选中其所属设备；选择设备时优先保留该设备当前选中会话，否则选择该设备最近的活跃会话。没有活跃会话时展示设备声明的视频频道和启动入口。

播放器仅在媒体服务确认会话可播放并取得签名播放信息后挂载。requested、starting、stopping、failed 等状态使用明确状态卡，不把“已创建数据库会话”等同于已有画面。

### 5. 启停直播保持现有 API，但补齐频道标识与变更回调

频道启动控件提交现有 `POST /devices/{id}/live-streams`，并显式携带所选 `streamKey`。接口返回后工作台选择新会话，立即刷新快照，并在过渡态期间短周期刷新，直到进入稳定状态或超时。停止操作沿用现有停止接口和状态机。

普通稳定状态不做永久高频轮询；设备命令或直播变更后立即失效并刷新，直播处于过渡态时使用有界轮询。后续可在不改变组件契约的情况下用服务端事件推送替换刷新器。

### 6. 设备管理移除日常动作，只保留进入工作台的入口

设备树和设备详情继续展示资产归属、拓扑、DeviceType、Driver、能力、连接状态和诊断信息。`DeviceActionPanel` 中的直播及控制入口迁到实时作业，设备管理提供携带 `deviceId` 的“进入实时作业”链接。

这样资产配置权限与运行控制权限在交互上分离，但仍共享统一设备实体和 RBAC 资源。

### 7. 现有历史能力作为当前设备的次级信息保留

总览不再展示完整历史时间线。若现有实时页面需要历史回看，则将时间线作为选中设备的次级、默认收起面板保留，并按当前设备过滤；本次不扩展历史查询和回放能力。

## Risks / Trade-offs

- **态势快照变大：** 授权动作和频道摘要会增加响应体。通过只返回 UI 必需字段、复用批量查询并避免逐设备查询控制成本。
- **状态短暂不一致：** 命令提交、设备回执和媒体就绪之间存在延迟。通过真实过渡态、有界刷新和失败原因展示避免乐观伪造。
- **选择联动复杂：** 地图、设备、直播和 URL 可相互更新。通过单一工作台 reducer/状态控制器和确定的优先级规则避免循环更新。
- **无坐标设备降低地图反馈：** 搜索选择器作为完整设备入口，地图只承担空间定位，并明确展示无位置状态。
- **授权投影可能过期：** 后端执行接口继续做最终鉴权；页面收到 403/冲突后刷新快照，不把客户端投影作为安全边界。
- **页面信息密度较高：** 使用响应式抽屉/分区和按能力出现的面板，移动端保持单列，不同时展开所有次级信息。

## Migration Plan

1. 抽取并测试服务端的有效能力/授权动作投影，扩展项目态势快照。
2. 建立实时作业工作台和选择状态，在保留现有 API 的情况下接入设备控制与直播。
3. 将项目总览替换为只读地图，将设备管理动作替换为工作台深链接。
4. 运行单元、集成和浏览器演示测试，重点验证跨项目参数、权限、无坐标设备和直播过渡态。
5. Web 端可通过恢复原页面组合方式回滚；本次无数据库迁移，Worker 与媒体服务无需回滚。

## Open Questions

- 稳定状态的设备遥测最终采用项目事件推送还是低频快照刷新，可在现有事件能力性能评估后决定；本次组件通过统一刷新接口隔离该实现差异。
