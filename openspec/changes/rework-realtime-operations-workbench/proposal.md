## Why

当前“总览”和“实时作业”都渲染完整的态势地图、时间线与直播面板，职责重复；设备控制又集中在设备目录中，启动直播后无法在原操作上下文直接查看或切换频道。需要将项目概览与实时操作台明确分层，让用户先从地图了解全局，再在实时作业中围绕一个具体设备完成查看、直播和控制。

## What Changes

- 将项目总览收敛为只读项目摘要与态势地图，不再承载完整直播、设备控制和历史时间线工作流。
- 将实时作业改造成面向单个选中设备的操作工作台：设备选择、地图联动、状态详情、实时通道、能力操作和诊断共享同一上下文。
- 在实时作业中展示项目全部活动直播频道，支持按设备/视频通道启动、切换、停止和查看 `requested`、`starting`、`live`、`degraded` 等真实状态。
- 启动直播后留在实时作业页面并自动选中新会话，不再要求用户返回总览或刷新页面寻找播放器。
- 将设备目录定位为资产、拓扑、DeviceType、Driver、能力和连接诊断页面；移除日常操作按钮，提供“在实时作业中打开”的深链接。
- 对没有地图坐标的设备提供可搜索设备选择器；地图选择与设备/直播选择双向同步。
- 保持现有项目、设备范围 capability RBAC、安全互锁、统一命令账本、直播状态机和播放鉴权边界，不增加前端直连厂商接口。
- 非目标：本变更不新增 DJI 协议命令、不改变 Driver/DeviceType 模型、不创建独立直播页面，也不重新设计任务编辑器。

## Capabilities

### New Capabilities

- `realtime-operations-workbench`: 定义项目总览与实时作业的职责分离、单设备操作上下文、地图/设备联动、活动直播频道选择及能力驱动控制体验。

### Modified Capabilities

无。当前主规格目录尚未同步对应能力，本变更以新的工作台能力描述用户可见行为，并复用现有 DJI、直播和统一设备平台契约。

## Impact

- Web 页面：项目总览、实时作业、设备目录。
- Web 组件：`SituationExplorer`、地图详情区、设备操作面板、直播面板及设备树。
- 数据读取：项目快照需要返回当前用户已授权的设备 actions、可用实时通道和足够的直播会话关联信息；所有查询继续限制 `project_id` 与当前用户权限。
- API：复用现有设备命令、直播启动/停止和播放 API；直播启动 UI 将显式传递服务端声明的视频 `streamKey`。如需无刷新状态收敛，可扩展现有项目事件订阅或增加受项目授权的轻量刷新端点。
- 数据库和 Worker：预计无需迁移或协议变更；现有直播会话与命令账本保持兼容。
