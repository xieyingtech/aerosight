## Purpose

定义统一应用的构建交付、配置初始化、数据库升级、后台协调与故障恢复要求，使操作者能够通过一个应用服务运行原有前后端能力，并对失败启动、滚动状态和版本回退获得可验证结果。

## ADDED Requirements

### Requirement: 单应用交付

系统 SHALL 交付包含静态前端和迁移 SQL 的 Go 可执行文件，单个应用进程提供前端、API、回调和后台任务；数据库、消息与媒体基础设施可以独立运行。

#### Scenario: 干净运行环境

- **GIVEN** 环境无 Node.js/pnpm 且基础设施可用
- **WHEN** 直接启动已发布二进制
- **THEN** 页面、登录、API、后台任务与回调正常，只有一个应用监听端口

#### Scenario: 缺失前端产物

- **GIVEN** 生产构建未生成或未复制静态前端
- **WHEN** 尝试构建生产二进制
- **THEN** 构建失败，不产生缺页的成功发布包

### Requirement: 迁移历史兼容与启动门槛

系统 SHALL 保留历史迁移文件校验、执行顺序、账本、基线采纳和互斥锁；配置或迁移失败 MUST 阻止业务就绪，迁移不得重复执行已完成项。

#### Scenario: 现有库升级

- **GIVEN** 数据库含有效的历史迁移账本与业务数据
- **WHEN** 启动新版本执行待迁移项
- **THEN** 只执行未应用项，保留账号、凭据、业务数据与历史校验和

#### Scenario: 历史文件被改

- **GIVEN** 已应用迁移的校验和与发布包不符
- **WHEN** 启动或执行 migrate
- **THEN** 明确失败，业务不 ready，不自动接受新校验和

#### Scenario: 并发与重复启动

- **GIVEN** 两个迁移执行者同时指向同一数据库
- **WHEN** 执行待迁移项后再次运行
- **THEN** 互斥执行且每项只应用一次，重复运行无额外副作用

#### Scenario: 空库初始化

- **GIVEN** 数据库为空且 PostGIS 可用
- **WHEN** 执行首次启动
- **THEN** 完成完整迁移与初始化；后续启动不重置既有管理员

### Requirement: 运行状态与优雅退出

系统 SHALL 统一管理 HTTP 与后台组件状态，必要组件失败使 readiness 失败；退出时停止领取任务、关闭长连接并在默认 30 秒预算内协调释放资源。

#### Scenario: 必要后台失败

- **GIVEN** HTTP 存活但必要消费者不可用
- **WHEN** 请求 /readyz
- **THEN** 返回非就绪并协调失败处理，而 /healthz 仍反映实际进程存活

#### Scenario: 正常停止

- **GIVEN** HTTP、SSE 和后台任务正在运行
- **WHEN** 进程收到退出信号
- **THEN** 先撤销 ready、停止领新任务，关闭 SSE 并排空可完成工作，再释放连接

#### Scenario: 任务未完成

- **GIVEN** 退出预算耗尽时任务仍未完成
- **WHEN** 应用退出并重启
- **THEN** 任务由原 outbox/租约恢复，不被提前标记成功或无条件重复副作用

### Requirement: 配置与回滚兼容

系统 SHALL 保留历史凭据解密所需密钥语义，新增配置在启动前验证；回滚不得自动执行破坏性数据库降级，部署过程必须说明首次重新登录。

#### Scenario: 历史凭据

- **GIVEN** 已有加密的设备、算法或 AI 配置
- **WHEN** 新服务使用原密钥读取配置
- **THEN** 正常解密，前端静态产物不出现密钥

#### Scenario: 缺失新密钥

- **GIVEN** 生产缺少有效 CSRF 密钥
- **WHEN** 启动应用
- **THEN** 明确失败且不进入 ready

#### Scenario: 版本回退

- **GIVEN** 升级增加了会话等兼容表，保留旧发布包和配置
- **WHEN** 停新服务后恢复旧 Web/worker
- **THEN** 旧业务可以运行，新增表保留，不自动删除或回退业务数据
