## Context

见 proposal.md。平台已有 run_algorithm 授权、算法标准化检测结果、媒体读取器和有界模型图像输入。聊天历史只保存工具摘要与证据链接。

## Goals / Non-Goals

**Goals:** 同一查询技能支持类别查询、属性复核、追问筛选与结果交付；所有框引用真实不可变运行。

**Non-Goals:** 本轮不增加任意类别定位、实时视频识别、几何地理定位或违规自动判定。

## Decisions

1. 内置 Markdown 通过 Go embed 打包。load_skill 只接受白名单名称，查询 Skill 返回固定版本及内容；系统指令要求目标查询先加载规则。与仅展示文件相比，规则真正进入模型上下文。
2. query_objects 不传 runId 时列出当前项目最近检测运行；指定运行时使用既有项目限定查询。labels 为模型从中文意图映射到已有模型类别的精确标签，minConfidence 为确定性阈值。
3. 语义筛选是两次读取：第一次输入实际候选框和图像，第二次传 selectedDetectionKeys 与理由；服务验证所有 ID，拒绝不存在或不满足过滤条件的框。空数组明确代表零匹配，不退回全部。
4. 图像依据运行的 inputAsset 版本和 checksum 读取，校验权限并禁止变化后的素材参与复核。返回整图和最多 8 张候选裁剪，各图有 ID 文本上下文；超限和图像不可用明确报告，模型不得以未看过的图认定属性。
5. 可复现选择编码为算法详情页的重复 object 参数，摘要和稳定证据链接使用现有历史保留机制；理由保存在脱敏摘要。结果页再核验 ID，未知 ID显示错误，导出模型预测及人工复核状态。

## Risks / Trade-offs

- YOLO 漏检 → 明确仅在检测候选中筛选，不声称开放词汇或全场无目标。
- 图像复核使用云端模型 → 请求图像会上传至配置的 AI Provider；Skill 中明确这一分工。
- 图像变化或媒体不可用 → 保留检测数据，禁用视觉判断并显示原因。
- 目标过多 → 有界预览且显示覆盖范围；不得把未复核候选判定为已排除。

## Migration Plan

无需数据库迁移。构建并重启应用即可使用；回滚到旧应用忽略新工具记录的标准证据链接，既有数据不变。
